# Design, motion and theme

Moved verbatim from `CLAUDE.md` on 2026-11-24. Read before changing anything visual: several details below are load-bearing.

## Tech and design

- Built with **Astro 5** (static site generation) + `@astrojs/sitemap`. **No client framework** - React and `@astrojs/react` were removed when the site was cut down to one screen; the only JavaScript that ships is the theme toggle in `Home.astro` and the pre-paint theme script in `Base.astro`. Do not reintroduce a framework for text.
- Styling: **Tailwind CSS 4** via `@tailwindcss/vite` (registered in `astro.config.mjs` under `vite.plugins`); base styles, tokens and `.doc` (privacy pages) live in `src/styles/global.css`.
- Package manager: **bun** (lockfile `bun.lock`).
- Bilingual via Astro i18n: Polish at `/` (default locale), English at `/en/`. Config in `astro.config.mjs`.
- Translations: `src/i18n/pl.json` + `src/i18n/en.json` - deliberately tiny. Loader + meta helpers in `src/i18n/index.js`.
- Layout + SEO head: `src/layouts/Base.astro` (meta, canonical, hreflang, Open Graph, Twitter Card, JSON-LD Person + WebSite). The JSON-LD carries no `makesOffer`/`knowsAbout` - the page does not describe services, so neither does its structured data.
- Page content: `src/components/Home.astro` - the entire site. One viewport, no scroll: a flex column inside a single `max-w-[1100px]` axis, with the locale link and theme toggle top-right, the `<h1>` wordmark plus one general sentence and the contact links optically centered, and the privacy link bottom-left. Every edge lands on the same two axes; that alignment is the whole design, so keep header, main and footer inside that one wrapper.
- Pages: `src/pages/index.astro` (PL), `src/pages/en/index.astro` (EN), `src/pages/{prywatnosc,en/privacy}.astro`, `src/pages/404.astro` (single bilingual 404, served by GitHub Pages for every missing path, noindex, does not use Base).
- The wordmark is the monogram written out: `<span data-glyph="a1">A</span>drian<span data-glyph="dot">.</span><span data-glyph="a2">A</span>ntosiak`, the dot in the accent. The spans are landing targets for the intro, so keep them and keep them adjacent - a newline between them renders as a space. `aria-label="Adrian Antosiak"` on the `<h1>` keeps the spoken name a name.
- Entry intro: `src/components/Intro.astro`. The A.A mark assembles out of the same 9.6 x 24 character cells the pointer reveal uses (positions snapped to that grid and de-duplicated), holds, then **collapses onto the wordmark** - the left A onto the A of "Adrian", the period onto the accent dot, the right A onto the A of "Antosiak" - fading out as the real letters rise through it. About 1.6s, then the canvas removes itself. An `is:inline` pre-paint script sets `--rise-base: 1.05s`, which every `.aa-rise` delay is offset by via `calc()`; with no JS or under `prefers-reduced-motion` the base stays `0s` and the copy appears at once. Four things it must keep doing, each of which cost an iteration:
  - `#aa-intro` needs explicit `width: 100%; height: 100%`. A canvas is a **replaced element**: with `width: auto` it takes its attribute size as its CSS size and `inset: 0` cannot stretch it, so at DPR 2 the drawing lands in the corner at double scale.
  - Landing targets are measured **when the collapse starts**, not at load. A canvas `measureText` probe run at load reports the *fallback* font's cap height (JetBrains Mono is not in yet) and every letter lands about a fifth short.
  - The wordmark's resting box is `getBoundingClientRect()` minus its live transform. The reveal paints rather than moves today, so that transform is identity; the subtraction stays because an earlier translate-based reveal put a permanent 14px error into every landing.
  - The collapse has **no per-cell stagger**: the mark has to travel as one rigid object, or the handoff reads as a hundred dots scattering.
- Motion otherwise: one entry reveal, and **every** element is in it - the wordmark, the services line, the contact links, and the chrome too (locale link, theme toggle, privacy link). `.aa-rise` (the name predates the effect) paints an element in from the left with `clip-path` in `steps(14, end)`, the same wipe the hover highlight uses, so the page has one motion language instead of two. Delays are inline, ordered content-then-chrome (0.16 / 0.28 / 0.40 / 0.52 / 0.58 / 0.64s), each offset by `--rise-base` - so until the monogram lands, the screen holds nothing but the monogram. Nothing else moves except the theme wipe and the pointer reveal.
  - The fill mode is **`backwards`, not `both`**, and that is load-bearing. `backwards` holds the clipped from-state through the delay so nothing flashes in early, and leaves no clip behind afterwards. With `both`, a stepped animation rests on its last step - one fourteenth still clipped - and the shortest labels lose their final character permanently.
  - `404.astro` runs the same reveal; with no intro on that page `--rise-base` falls back to `0s` and the sequence starts at once.
- Headless visual verification: `bun <scratchpad>/shots.mjs` pattern - playwright-core (devDep) + system Chrome headless, real viewports (incl. 390px), `colorScheme` per run, screenshot. Worth asserting `scrollHeight <= innerHeight`: the page is supposed to fit one screen.
- Design system: **two themes**, palette **Catppuccin** - Mocha for dark, Latte for light - because that is the theme this site's author runs in Ghostty (`theme = Catppuccin Mocha`), and the accent `#ff8c42` is that same config's `split-divider-color`. Tokens live in `src/styles/global.css`: the Tailwind 4 `@theme` block holds Mocha (`--color-bg #1e1e2e`, `--color-ink #cdd6f4` - 11.3:1, the ratio the Ghostty config notes for its foreground -, `--color-ink-2 #a6adc8`, `--color-ink-3 #9399b2`, `--color-line #45475a`, `--color-line-2 #585b70`, `--color-accent #ff8c42`), `:root` inside `@variant theme-light` overrides with Latte (`#eff1f5` / `#4c4f69` / `#5c5f77` / `#676a80` / `#ccd0da` / `#bcc0cc`; ink-3 is one step darker than Latte subtext0 `#6c6f85`, which only reaches 4.37:1, for 4.70:1) and darkens the accent to `#b34d00`, since `#ff8c42` only reaches 2.6:1 on paper. Every ink grade clears 4.5:1 on its own ground - check before changing one. All markup uses token utilities (`text-ink`, `text-ink-3`, `decoration-line`, `text-accent`) - never raw hex or white/black classes, or the element won't re-theme. `::selection` is a surface block (`--color-line-2`), the way a terminal selection looks, not an ink inversion.
- Typography: the page is **mono** - JetBrains Mono (Ghostty's own default face) on the whole page wrapper, at `0.9375rem` / `1rem` (15-16px at the default 16px root) with `leading-[1.6]`, echoing the config's `font-size = 16` plus `adjust-cell-height = 12%`. Every font size is in **rem**, never px, so a larger browser text setting scales the page: the rails are `0.6875rem` (11px), the 404 label `0.8125rem` (13px), and the headline `clamp(1.75rem, 0.48rem + 5.2vw, 3.25rem)` - 28-52px, tuned to render exactly what the old `clamp(28px, 6.2vw, 52px)` did at the default root at 390 / 768 / 1100 / 1440 / 1920px widths. Nothing pins the root size in px. At a 20px root the page still fits one screen at 1440x900 and 390x844. Px stays only on measures that are not font sizes: the 9.6 x 24 canvas cell grid of the intro and the pointer layer, layout widths, underline offsets and the mask radius. Inter Tight stays loaded and is used only by `.doc` (the privacy pages), where sans reads better for prose. Both are **self-hosted** variable woff2 in `public/fonts/` (latin + latin-ext subsets; `@font-face` in `global.css`, preloads in `Base.astro`). No Google Fonts CDN - the privacy policy states fonts send no data to external providers; keep it that way.
- Hover is inverse video, not a web underline. `.aa-rev` carries it, in two forms. An element with no text (the icon button) flips whole. An element with `data-label` gets the highlight **swept in left to right** over 160 ms: a `::before` overlay holds the same string inverted and is revealed by `clip-path`, so the text changes colour exactly where the block has reached and never sits unreadable over a half-drawn ground. `data-label` must match the element's own text - it is the overlay. Inline padding is cancelled by an equal negative margin, so nothing shifts. Three states drive it: `:hover` behind `@media (hover: hover)` so touch never sticks, `:focus-visible` for the keyboard, and `:active` for touch (instant there, no sweep) - plus `-webkit-tap-highlight-color` tinted to the accent via `--rgb-accent` for browsers that paint their own tap flash.
- Pointer reveal: `.aa-grid` is a fixed, inert `<canvas>` painted with leftovers of a terminal buffer - faint, meaningless punctuation (`. : - + / \\ | _ = * ' \``) sitting in the same 9.6 x 24px JetBrains Mono cells the intro assembles from, about half of them filled - shown only through a soft 190px radial `mask-image` that the pointer drags around. While the layer is visible, the script rewrites a few dozen random cells within 150px of the pointer every 70 ms, so the buffer keeps churning as if something were still computing; nothing outside that circle is ever repainted. The loop (rAF plus the 70 ms churn tick inside it) stops 3 s after the last `pointermove` - the layer stays visible where it is, it just stops changing, because moving content that runs past five seconds needs a pause control and a still pointer is that pause - and the next move restarts it. It also stops on pointer leave. The glyph ink is the element's CSS `color` (`--color-grid`), read by the script, so it re-themes; the buffer is repainted on `document.fonts.ready`, on resize and on a `data-theme` change. Position is written as `--x` / `--y` custom properties on rAF, so a move costs one style write and no layout. The canvas is **created by the script**, not written in the markup: Astro's compiler moves a `<canvas>`'s closing tag past whatever follows it, which swallowed the entire page into the layer. It is gated on `(hover: hover)` and on `prefers-reduced-motion` being absent, so touch and motion-sensitive visitors never get the element at all; the CSS also hides it under reduced motion outright. The content wrapper carries `relative z-10` to sit above it. There is deliberately no readable text in the buffer - it must never grow into a fake prompt or command output. Earlier versions - a bare line grid, and before that a caret jumping between lines on hover - were rejected, and are not to come back.
- The one terminal signal is `.aa-cursor`: a blinking accent beam (thin, standing taller than the caps) after the services line (`cursor-style-blink = true` in the config, hence the blink). The blink is **finite**: `animation-iteration-count: 4`, about 4.2 s, then the animation ends and the beam rests solid and visible (no fill mode, so the end state is the unanimated, opaque one) - blinking that runs past five seconds would need a pause control, and `prefers-reduced-motion` does not replace one. Under reduced motion it never blinks. It is centered on the **cap band**, not the line box - `vertical-align: middle` lands at baseline minus half x-height, so `position: relative; top: -0.09em` makes up the difference to half cap-height. Changing the font or the size means re-checking that nudge. There is deliberately **no** fake prompt line, window chrome, typing animation or command output - one character carries the register.
- Theme switching: a pre-paint inline script in `Base.astro` (and `404.astro`) resolves stored choice > `prefers-color-scheme` > dark, and sets `data-theme` on `<html>` plus every `meta[name=theme-color]` - no FOUC. Without JS there is no `data-theme`, and the page follows the system instead: `global.css` defines two Tailwind custom variants, `theme-light` and `theme-dark`, each matching either the attribute or (when `<html>` has no `data-theme`) the matching `prefers-color-scheme`, and every theme-dependent rule - the Latte tokens, `color-scheme`, the icon selection - is written once inside one of them. `:root` defaults to `color-scheme: light dark`, never a hardcoded scheme; the variants pin it. The head carries two theme-color metas, `#eff1f5` with `media="(prefers-color-scheme: light)"` first and an unqualified `#1e1e2e` fallback, so the no-JS page gets the right bar color; the scripts set both to the resolved theme. The same script keeps listening: while nothing is stored it follows a live system theme change, and a `storage` event lets other open tabs follow a change of `aa_theme` (both instant, no wipe). The toggle ships both icons and the theme variants on `.only-dark` / `.only-light` pick one, so the correct glyph is right at first paint, with or without JS. The flip runs inside `document.startViewTransition` and animates `::view-transition-new(root)` as a 420 ms circular `clip-path` wipe growing from the control (MDN's reveal recipe; keyboard activation reports `clientX/Y` 0, so the origin falls back to the control's own center). `global.css` drops the UA cross-fade (`isolation: auto`, `animation: none`, `mix-blend-mode: normal` on the root old/new pseudos). No `startViewTransition` or `prefers-reduced-motion: reduce` - instant flip. `localStorage("aa_theme")` is the only thing stored - and only when the choice differs from the system theme; picking the system theme removes the key - and the privacy policy (both locales) says exactly that - keep it true.
- Scripts: `bun run dev` (local), `bun run build` (writes `dist/`), `bun run preview`.

## Image assets (in `public/`)

- `public/favicon.svg`, `public/favicon.ico` (32x32), `public/apple-touch-icon.png` (180x180), `public/og.png` + `og-en.png` (1200x630 share cards). The **icon** runs on the light palette (Latte `#eff1f5` ground, `#4c4f69` mark, `#b34d00` period): a browser tab is usually light chrome and a pale square reads there far better than a near-black one. The **share cards** stay on the Mocha ground with `#cdd6f4` marks, matching the site's default theme; both carry the monogram's square period in the accent, and the card's name takes the same accent dot as the page wordmark. The share card is the page itself - mono name, the services line, the accent cursor beam.
- All four are generated from inline SVG templates in `scripts/generate-assets.mjs` via `sharp` (devDep). Edit the SVG templates in that script, then run `bun run assets` to regenerate. Commit the regenerated binaries.
